# Installable app (PWA) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SkyTeam installs as an app (Android, iOS, desktop Chrome/Edge): its own icon and window, the app shell from a service worker, the seat kept when the phone closes the app, and updates that never interrupt a game.

**Architecture:** `vite-plugin-pwa` (Workbox `generateSW`) generates the manifest and a service worker that precaches the app shell (index.html + hashed `/assets/*`) and leaves everything live (`/api`, `/rooms`, `/identity`, `/socket.io`) to the network. A small `pwa/` module in the client holds the installed-app behaviour: whether we run installed, where the identity token lives, the room to resume on launch, and the update bar. The edge proxy lets the PWA's files past the site's password gate.

**Tech Stack:** React 18, Vite 6.4, `vite-plugin-pwa@1.3.0` (+ `workbox-window@7.4.1`), nginx, Caddy, Vitest + jsdom, Playwright (manual checks).

**Spec:** the design agreed in chat on 2026-10-11 (no separate spec file): PWA, keep the password gate with the PWA files exempt, icons drawn from the plane icon, no store listing.

## Global Constraints

- Dependencies pinned exactly, each released ≥ 2 weeks before use: `vite-plugin-pwa@1.3.0` (2026-05-05), `workbox-window@7.4.1` (2026-05-04), `@vite-pwa/assets-generator@2.0.0` (2026-09-12, one-off, not a dependency). Not `vite-plugin-pwa@2.0.0` (2026-10-03, too new).
- No local Node: every npm/vitest/build command runs in `node:22-alpine` with the repo mounted (`docker run --rm -v "$PWD":/app -w /app node:22-alpine sh -c "..."`).
- The CSP in `packages/client/security-headers.conf` stays as it is (`default-src 'self'` already allows a same-origin manifest and worker).
- Browser tabs keep today's identity rule: one tab = one player (`window.name` + `sessionStorage`). Only the installed app changes.
- Copy, labels and comments follow the codebase's style: plain sentences, British "colour", no emoji.

## Review Focus

1. **Launching the installed app after the room is gone** (closed by the host, expired): it must land on the home page once, not retry a dead invite on every launch. → test in Task 2.
2. **Leaving a room in the installed app**: the next launch must not pull the player back in. → test in Task 2.
3. **A new version while a game is on**: no bar, no reload; the bar appears once back in the lobby/home. → test in Task 3.
4. **Opening an invite link with the app installed** (the URL has `?join=`): that invite wins over the remembered room. → test in Task 2.
5. **Storage blocked** (private mode, site data blocked): the installed-app paths must fall back like the name storage does, never throw. → test in Task 2.

### Task 2: The installed app keeps its seat

**Files:**
- Create: `packages/client/src/pwa/installed.ts`
- Modify: `packages/client/src/api.ts` (token storage goes through `installed.ts` when installed)
- Modify: `packages/client/src/App.tsx` (remember / forget the room)
- Modify: `packages/client/src/main.tsx` (resume before the first render)
- Test: `tests/client/pwa.test.tsx`

**Interfaces:**
- Produces: `isInstalled(): boolean` (`matchMedia("(display-mode: standalone)")` or iOS `navigator.standalone`); `rememberRoom(inviteCode: string | null): void`; `resumeRoom(): void` (on `/` without `?join=`, puts the remembered room's `?join=` in the URL); `installedToken` / `storeInstalledToken`.

- [ ] Write the failing tests:
  - Installed: the token is kept in `localStorage` and read back after `sessionStorage` and `window.name` are cleared, i.e. the app was closed.
  - In a tab: the token stays per tab, as now (an existing app test already covers this).
  - Installed, launched at `/` with a remembered room: the URL becomes `/?join=CODE` before `App` mounts, and the join request is sent with the kept token.
  - `?join=OTHER` in the launch URL wins, and becomes the remembered room.
  - Leaving the room (`Leave room`) forgets it. A failed join (room gone) forgets it.
  - `localStorage` throwing: no exception, it behaves like a tab.
- [ ] Run them and see them fail.
- [ ] Implement `installed.ts`. Then `api.ts` `getStoredToken` / `storeToken` branch on `isInstalled()`. `App.tsx` calls `rememberRoom(code)` where it writes `?join=` and `rememberRoom(null)` where it resets to `/` or a join fails. `main.tsx` calls `resumeRoom()` before `render`.
- [ ] Run the tests and see them pass. Then the full suite.
- [ ] Commit.
